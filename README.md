# Збірник

## Що це

Церковний збірник пісень для двох груп користувачів: «Співаю / читаю» та «Музикант». Застосунок працює за принципом offline-first: зберігає пісні на телефоні та оновлює їх через API, коли є мережа. Першій групі потрібен текст, другій — акорди, транспонування, капо та параметри ритму.

## Структура монорепо

| Шлях | Призначення |
| --- | --- |
| `apps/mobile` | Застосунок React Native, Expo SDK 58 та Expo Router. |
| `apps/api` | API на Hono у Cloudflare Workers, база D1 та міграції. |
| `packages/shared` | Типи, парсер ChordPro, акорди, пошук, ритм і порівняння текстів. |
| `tools/import-notes` | Експорт Apple Notes, перетворення в ChordPro та генерація SQL. |
| `songs/` | Початкові пісні у файлах `.cho`. |

Пакети робочого простору задано в `pnpm-workspace.yaml`.

## Вимоги

- Node.js 24 та pnpm 12.
- Режим `nodeLinker: hoisted`, уже заданий у `pnpm-workspace.yaml`.
- Expo Go з підтримкою SDK 58 на телефоні.
- Телефон і компʼютер в одній мережі Wi-Fi.
- macOS та Apple Notes для експорту нотаток.
- `bash`, `curl` та `jq` для перевірки `pnpm smoke`.

## Швидкий старт

Виконуйте команди з кореня репозиторію.

1. Установіть залежності:

   ```sh
   pnpm install
   ```

2. Застосуйте міграції до локальної D1:

   ```sh
   pnpm db:migrate
   ```

3. Завантажте початкові пісні:

   ```sh
   pnpm db:seed
   ```

   Команда генерує `apps/api/seed.sql` із `songs/` і виконує SQL у локальній D1. Повторний запуск оновлює змінені пісні, а не дублює їх. ID залежить від відносного шляху файла: зберігайте шлях під час редагування. Видалення `.cho` саме по собі не видаляє пісню з D1.

4. Запустіть API:

   ```sh
   pnpm api
   ```

   Скрипт виконує `wrangler dev --ip 0.0.0.0`. API слухає порт `8787`.

5. В іншому терміналі запустіть мобільний застосунок:

   ```sh
   pnpm mobile
   ```

   Скануйте QR-код у Expo Go. Дочекайтеся першої синхронізації, перш ніж працювати без мережі.

`apps/mobile/src/lib/api.ts` бере хост Metro з `Constants.expoConfig.hostUri` та додає порт `8787`. Якщо хост відсутній, використовує `localhost`. Щоб задати адресу вручну, запустіть:

```sh
EXPO_PUBLIC_API_URL=http://<ip>:8787 pnpm mobile
```

Замініть `<ip>` на локальну IP-адресу компʼютера.

## Вхід і ролі

Читати пісні можна без входу. Для входу через magic link введіть email, а потім 6-значний код із листа. Посилання та код діють 15 хвилин.

У `apps/api/wrangler.jsonc` задано `DEV_MODE=true`. У цьому режимі API повертає `devCode`, а застосунок підставляє його у форму. Без `RESEND_API_KEY` API також друкує лист із кодом у консолі Wrangler.

Для надсилання листів скопіюйте `apps/api/.dev.vars.example` у `apps/api/.dev.vars` та задайте `RESEND_API_KEY`. Задайте адресу відправника в `MAIL_FROM` у `apps/api/wrangler.jsonc`.

Ролі API: `member`, `musician` та `admin`. Адміністратор керує ролями, редагує спільні пісні та розглядає пропозиції. Список `ADMIN_EMAILS` у `apps/api/wrangler.jsonc` має пріоритет над роллю в базі; початкове значення — `admin@example.com`. Режими перегляду «Співаю / читаю» та «Музикант» задають спосіб показу пісні.

Deep link `songbook://login?email=…&token=…` працює у dev-збірці. В Expo Go схема `songbook://` не відкриває застосунок. Вводьте 6-значний код.

## Як увімкнути Apple / Google

### Apple

`expo-apple-authentication` уже встановлено. Для Expo Go audience дорівнює `host.exp.Exponent`; це значення вже є в `APPLE_AUDIENCE`.

Для dev- або production-збірки змініть `ios.bundleIdentifier` у `apps/mobile/app.json`: початкове значення — `com.example.songbook`. Додайте свій bundle ID до `APPLE_AUDIENCE` у `apps/api/wrangler.jsonc`. Розділяйте кілька значень комами. Параметр `ios.usesAppleSignIn` уже має значення `true`.

### Google

Сервер реалізує `POST /auth/google` та перевіряє ID token через `jose` і JWKS Google. Задайте OAuth client ID у `GOOGLE_AUDIENCE` у `apps/api/wrangler.jsonc`. Розділяйте ID для iOS, Android і web комами.

Клієнтський вхід Google ще потрібно підключити. Для нього потрібна dev-збірка:

1. Перейдіть у `apps/mobile` та встановіть пакет:

   ```sh
   cd apps/mobile
   npx expo install @react-native-google-signin/google-signin
   ```

2. Додайте config plugin `@react-native-google-signin/google-signin` до `plugins` у `app.json` та налаштуйте OAuth для платформи.
3. Створіть і запустіть dev-збірку командою `npx expo run:ios` або `npx expo run:android`.
4. Отримайте `idToken` через Google Sign-In та передайте його в `signInWith('google', idToken)` з `apps/mobile/src/lib/auth.tsx`.

API звʼязує вхід Apple або Google з наявним акаунтом за підтвердженим email.

## Імпорт з Apple Notes

Почніть із кореня репозиторію.

1. Експортуйте теку «Пісні» разом із вкладеними теками:

   ```sh
   osascript -l JavaScript tools/import-notes/export-notes.js "Пісні" ./notes-export
   ```

   Надайте доступ до Notes, якщо macOS запитає його.

2. Перетворіть HTML або текстові файли на `.cho`:

   ```sh
   pnpm --filter @songbook/import-notes convert ../../notes-export ../../import-out
   ```

   Додайте `--mono`, якщо нотатки мають моноширинний текст. HTML із відомим моноширинним шрифтом розпізнається автоматично. В інших випадках конвертер рахує позиції акордів за приблизною шириною символів пропорційного шрифту Notes.

   Скрипти з `--filter @songbook/import-notes` працюють у `tools/import-notes`. Тому аргументи шляхів тут починаються з `../../`.

3. Перегляньте `import-out/report.json` і виправте попередження: `duplicate_number`, `no_number`, `no_chords`, `cyrillic_in_chords`, `suspicious_chord_line`, `mixed_h_b` (у пісні є і `H`, і `B` — оберіть одне). Перевірте позиції акордів у згенерованих `.cho`.
4. Скопіюйте перевірені `.cho` у `songs/`, зберігаючи потрібні вкладені теки.
5. Виконайте `pnpm db:seed`.

Конвертер розпізнає перший рядок на зразок `12. Назва` або `2 НАЗВА (H) (82)` (тональність і темп у дужках), рядок `4 cap`, заголовки з повтором `ПРИСПІВ: x2`, повторний приспів без вмісту (→ `{chorus}`) і рядок-посилання (→ `{link}`). Також він розпізнає метадані `Тональність`, `BPM`, `Темп`, `Розмір`, `Капо`, `Бій` та їхні російські й англійські відповідники. Заголовки секцій українською, російською та англійською перетворює на блоки: куплет → `{sov}`, приспів → `{soc}`, бридж → `{sob}`; інші (вступ, програш, outro) → `{c: …}`. Блок закінчується на порожньому рядку або наступному заголовку. Рядок акордів над текстом обʼєднує з текстом у ChordPro.

Щоб завантажити іншу теку без копіювання в `songs/`, згенеруйте SQL і виконайте окремий скрипт API:

```sh
pnpm --filter @songbook/import-notes to-sql ../../import-out ../../apps/api/seed.sql
pnpm --filter @songbook/api db:seed
```

Коренева команда `pnpm db:seed` завжди заново генерує SQL саме із `songs/`.

## Формат ChordPro

Зберігайте пісні в UTF-8 з розширенням `.cho`. Пишіть акорди у квадратних дужках перед відповідним складом.

```text
{title: Молитва}
{number: 12}
{key: Em}
{tempo: 72}
{time: 6/8}
{capo: 2}
{rhythm: ↓ ↓↑ ↓ ↓↑}
{accents: 1 4}
{notation: german}

{c: Куплет 1}
[Em]Тихо [H7]лине мо[Em]литва.
{start_of_chorus}
[C]Світло [Bb]в серці [Em]є.
{end_of_chorus}
```

Рядок лише з акордів (вступ, програш) записуйте тактами: `| [Am] - [F] | [C] - [G] |`. Риска `|` відділяє такти. Акорди в одному такті, розділені `-`, ділять його порівну: «Am - F» — по пів такту. Застосунок показує такі рядки сіткою тактів однакової ширини. У редакторі для цього є кнопки `|` і `-` у палітрі.

Якщо пісня має `{capo}`, акорди в ній — аплікатури для цього капо, а `{key}` — тональність, яка звучить. Наприклад, `{key: H}` і `{capo: 4}` з акордами G, C, Em, D. Застосунок за замовчуванням показує акорди як записано і пише «акорди як у G». Якщо поставити капо 0, він покаже реальні акорди: H, E, G#m, F#.

`{chorus: Приспів x2}` повторює останній записаний приспів (стандартна директива ChordPro). `{link: https://…}` додає посилання на повний текст пісні. Пісня без тексту (лише схема акордів) показує акорди і в режимі «Співаю / читаю».

`number`, `rhythm`, `accents`, `notation` і `link` — власні директиви збірника. `accents` задає номери акцентованих долей від 1. `H` і `B` — це сі, сі-бемоль пишіть `Bb` або `Hb`. Нотація впливає лише на підпис сі: якщо акорди містять `H`, застосунок показує сі як `H`, інакше як `B`. Сі-бемоль завжди показується як `Bb`. Директива `notation` може явно задати `german` (H) або `english` (B).

## Тести і перевірки

Виконуйте з кореня репозиторію:

```sh
pnpm test
pnpm typecheck
pnpm smoke
```

`pnpm test` запускає тести `shared` та `import-notes`. `pnpm typecheck` перевіряє типи пакетів; для API також генерує типи Wrangler.

`pnpm smoke` використовує окрему тимчасову локальну D1 у `apps/api/.wrangler/smoke` та порт `8788`. Перевіряє пагінацію sync, вхід, ролі, пропозиції, конфлікти версій, унікальність номерів і tombstones.

Для перевірки Android-експорту виконайте з кореня:

```sh
cd apps/mobile && npx expo export --platform android
```

## Як це працює

Після першої синхронізації застосунок читає пісні з локальної SQLite. Синхронізація запускається на старті, після повернення з фону та через pull-to-refresh.

Клієнт отримує зміни через `GET /sync?cursor=<updated_at>:<id>&limit=500`. API сортує записи за часом оновлення та ID, повертає наступний `cursor` і `hasMore`. Tombstones із `deletedAt` видаляють локальні копії; початкова синхронізація їх пропускає. Кожна сторінка та її курсор записуються однією транзакцією.

Пошук використовує FTS5 і `bm25` з вагою назви ×10. Якщо FTS5 недоступний, застосунок переходить на `LIKE`. Нормалізація зближує українські й російські варіанти літер, прибирає наголоси та апострофи. Також можна шукати за номером пісні.

Локальні overrides зберігають транспонування, капо та власний текст. Зміни тексту можна надіслати як пропозицію з `base_version` (`baseVersion` в API). Сервер перевіряє конфлікти версій, а адміністратор схвалює або відхиляє пропозицію. Таблиця `song_versions` зберігає історію спільних пісень. Альбоми та їхній порядок поки зберігаються лише локально.

- Історія версій в UI та тести UI.
